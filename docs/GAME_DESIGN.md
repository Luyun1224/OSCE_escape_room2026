# OSCE ESCAPE｜臨床解碼：最後一班值勤 — 遊戲設計文件

> The Last Shift — A Clinical Mystery
> 版本：0.1.0（Phase 1 可遊玩原型）　狀態：**臨床內容待教師審核**

---

## 1. 設計定位

| 項目 | 說明 |
|---|---|
| 類型 | Medical Mystery × Clinical Simulation × Escape Room |
| 對象 | 醫學生、UGY 實習醫學生、PGY1/PGY2 |
| 目標 | 以探索、互動解謎與臨床決策，訓練 OSCE 六大核心能力 |
| 平台 | 瀏覽器（GitHub Pages 靜態部署），不需登入 |
| 原則 | 不是題庫；每道謎題對應一項教育目標；推理過程比答對更重要；placeholder 必須透明標示 |

### 故事主線
午夜醫院啟動緊急管制，臨床資訊系統異常，病歷與交班資料遺失。玩家扮演值班 PGY 醫師。
貫穿六關的謎團：**一份時間戳為 01:58 的 12 導程心電圖**——但病人 02:10 才到院。這份心電圖屬於誰？
前一位值班醫師留下的殘頁：「請先確認他的用藥，不要急著——」。

## 2. 系統架構

```
src/
├─ engines/
│  ├─ scene/        Scene Engine       3D 場景、程序化 PBR 貼圖、鏡頭、後製、AssetSlot（GLB 載入／待補標示）
│  ├─ interaction/  Interaction Engine 物件點擊 → 規則比對 → 開啟面板／套用效果
│  ├─ narrative/    Narrative Engine   條件 (Condition) / 效果 (Effects) 求值；分支對話；團隊事件狀態機
│  ├─ case/         Case Engine        臨床病例資料（病人、生命徵象、線索資料庫）
│  ├─ puzzle/       Puzzle Engine      規則化謎題評估（問題表述重組）
│  ├─ assessment/   Assessment Engine  評核規準計分、面向加權、報告產生、JSON/CSV 匯出
│  └─ progress/     （由 store/gameStore 的 zustand persist 實作 Progress Manager）
├─ data/            所有內容資料化（TypeScript 設定檔）
│  ├─ level1/       dialogue · nurseEvents · objects · documents · objectives · puzzle
│  ├─ assessment/   level1Rubric（可觀察指標＋預設權重）
│  └─ levels.ts     六關資訊
├─ store/           gameStore（持久化遊戲狀態）、uiStore（介面暫態）
├─ audio/           Web Audio 程序化環境音與音效
└─ ui/              home · hud · panels · report（Dashboard）
```

### 資料流
```
點擊 3D 物件 ─► Interaction Engine ─► OBJECT 規則 (Condition) ─► Effects（線索/旗標/信任）
                                                       │
問診選項 ─► Narrative Engine ─► 回應 (when 條件) ──────┤
                                                       ▼
                                     gameStore.level1（事件紀錄 events[]）
                                                       │
                     ┌─────────────────────────────────┼──────────────────────┐
                     ▼                                 ▼                      ▼
            團隊事件觸發（狀態機）              推理板解鎖門檻          Assessment Engine
                                                                    （rubric.check(ctx)）→ 報告
```

所有臨床變化由 **資料中的條件** 決定，沒有任何隨機病況變化。

## 4. LEVEL 01｜消失的病歷 — 互動流程

**案例**：62 歲男性，急性胸痛（虛構，待教師審核）。

```
進入診察室 3
 ├─ (建議) 門邊乾洗手 ───────────────────────────────── C1 手部衛生
 ├─ 工作桌：檢傷單 ─► 線索：檢傷紀錄、基本資料
 ├─ 病床：林先生（分支問診，7 個主題、30+ 問題）
 │    ├─ 未自我介紹就發問 → 病人反問「你是哪一位？」
 │    ├─ OPQRST / 伴隨症狀 / 危急鑑別 / 背景史
 │    ├─ 嚴重度、病程、家族史 → 病人表達擔憂 → 解鎖「同理回應」與「不實保證」分支
 │    └─ 用藥：PDE5 抑制劑（隱藏線索，三條取得路徑）
 │         ① 信任感足夠時詢問「其他／自費用藥」→ 直接坦承
 │         ② 病人迴避 → 「保密說明」分支 → 坦承
 │         ③ 徵得同意查看藥袋 → 發現自費處方 → 追問
 │         ④ 直接具體詢問 PDE5 抑制劑
 ├─ 團隊事件（狀態機觸發）
 │    ├─ 問診 ≥2 題：12 導程心電圖 → 立即／延後／只接監視器
 │    ├─ 問診 ≥9 題：護理師詢問是否給 NTG
 │    │    ├─ 暫緩並確認 PDE5、血壓 ✔
 │    │    ├─ 給予（尚未知用藥）→ 病人主動說出 → 近乎失誤 (near miss) 攔截＋補救教學
 │    │    └─ 給予（已知用藥）→ 護理師攔截 → 不安全決策紀錄
 │    └─ 問診 ≥15 題：心電圖上傳後「消失」→ 劇情推進
 ├─ 監視器（即時波形）、白板、交班單殘頁、心電圖機（E-17）→ 劇情線索
 ├─ 臨床線索 ≥10 且已讀檢傷 → 解鎖「臨床推理板」
 ├─ 工作站：問題表述重組謎題
 │    ├─ 5 欄位：背景危險因子 / 症狀特徵 / 伴隨症狀 / 關鍵陰性 / 安全警示
 │    ├─ 拖曳線索卡 → 欄位（規則：依線索臨床標籤計數，誤置與低關聯分開統計）
 │    ├─ 假設：最可能診斷＋不可錯過之危急診斷
 │    └─ 故事模式：逐欄回饋；挑戰模式：總數回饋；評量模式：一次提交不回饋
 │       3 次未通過 → 可選「學習引導並繼續」（記錄為輔助完成，避免卡關）
 └─ 門禁解鎖 → 通關 → 學習報告
```

### 各模式差異
| | 故事探索 | 極限逃脫 | OSCE 模擬 |
|---|---|---|---|
| 計時 | 顯示經過時間 | 倒數（20/15/12 分） | 顯示經過時間 |
| 提示 | 不限 | 3 次（進階 2 次） | 3 次（記錄） |
| 決策回饋 | 即時（安全/次佳/風險＋教學） | 即時 | 不顯示，報告中解析 |
| 推理板回饋 | 逐欄位 | 僅總數 | 無，一次提交 |
| 時間到 | — | 可繼續照護或進入回饋，不強制中斷 | — |

### 難度
基礎：互動標記常駐；標準：淡化標記；進階：無標記。所有難度皆可按住 **Space** 顯示互動物件，避免因找不到熱區而無法完成臨床任務。

## 5. 評核與學習分析

- 規準：`src/data/assessment/level1Rubric.ts`（35 項可觀察指標，含 2 項關鍵安全項目）
- 六面向：病史詢問、身體檢查、臨床推理、決策與病人安全、技能流程認知、醫病溝通與資訊整合（Level 01 不評身體檢查與技能，報告中標示「本關未評」）
- 權重：預設值寫在規準檔；教師可在「設定 → 教師權重」即時調整（存於 localStorage）
- 記錄：完成項目、遺漏關鍵項目、錯誤決策、提示（依任務、依階段）、完成時間、推理路徑（完整事件序列）、病人安全行為
- 速度不等於能力：用時只呈現，不計分
- 不推算 EPA：報告明文聲明；EPA 對應需另建經教師確認之規準
- 匯出：JSON（完整報告＋原始事件）、CSV（meta / domain / item / decision / event 列）

## 7. 開發階段

### Phase 1｜可遊玩原型 ✅（本版本）
首頁、玩家設定、任務簡報、Level 01 3D 診察室、場景探索、病人分支問診、線索背包、病歷筆記、團隊決策事件、臨床推理板（問題表述謎題）、三階段提示、三種模式、通關畫面、學習報告、JSON/CSV 匯出、教師權重、自動存檔與重新開始、GitHub Pages 部署。

### Phase 2｜六關擴充（共用架構）
| 關卡 | 場景 | 核心機制（規劃） |
|---|---|---|
| L02 身體留下的訊號 | 模擬診察室 | 身體部位熱區＋器械選擇（聽診器等）；檢查目的與發現紀錄；以教師審核之圖片／聲音呈現 |
| L03 數據背後的秘密 | 檢驗與影像判讀室 | 證據拖曳至假設、支持／反證配對、下一步檢查選擇；判讀消失的 01:58 心電圖 |
| L04 危急時刻 | 急救區 | 互動監視器；經審核之案例狀態機（決策 → 狀態轉移）；延遲辨識與遺漏紀錄；後果＋補救學習 |
| L05 關鍵操作 | 技能訓練室 | 12 導程心電圖操作：準備、器械、步驟排序、病人安全確認、操作後處置（明確標示為「認知流程訓練」，不評估手部技能熟練度） |
| FINAL 最後的交班 | 交班室 | 病人摘要、SBAR、風險與後續處置、回應團隊提問；整合全部關卡資料之總報告 |
